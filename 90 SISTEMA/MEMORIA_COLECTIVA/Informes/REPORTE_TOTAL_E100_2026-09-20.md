### 2.2. Flujo diario recomendado (mañana / mediodía / noche)

#### MAÑANA (activación — 15-25 min)

1. Abrir Notion: Bóveda de Autoridad + Monitor de Integridad.
2. Registrar sueño, NoFap, dieta (checklist Ultron) + energía 0.0–1.0.
3. Revisar Orden de Batalla + Radar Temporal: ¿qué vence hoy / esta semana?
4. Abrir Obsidian `07_TABLERO/HOY.md`: copiar 3 prioridades desde Notion.
5. Abrir Todoist: crear / limpiar tareas de hoy (máximo 5-7 micro-tareas).
6. Elegir tarea ancla con energía ≥0.7; si energía <0.7, tarea ligera + mantenimiento.
7. Iniciar Diario de Guerra `01_DIARIO_DE_GUERRA/01_Daily_Logs/[fecha].md`.

#### MEDIODÍA (micro-auditoría — 5-10 min)

1. Check Todoist: ¿qué se cerró? ¿qué se atascó?
2. Actualizar energía en Notion (Monitor de Integridad 2.0).
3. Si apareció idea o apunte: capturar a `00 ENTRADA (Inbox)`, no procesar aún.
4. Si surgió imprevisto con fecha: crear en Notion Pipeline / Invasión Semanal.
5. Re-priorizar tarde: 1 pesada + 1 ligera como máximo.
6. Registrar interferencia en Escudo Shard si hubo distracción (Log de Interferencia).

#### NOCHE (cierre + transmutación — 15-20 min)

1. Cerrar Todoist: marcar completadas, migrar no hechas a mañana o a Notion.
2. Actualizar `HOY.md` y `TABLERO_SEMANAL.md` en Obsidian (espejo, no gestión).
3. Procesar Inbox si tiene >48h: clasificar a PARA o archivar a `40 ARCHIVOS X`.
4. Escribir Post-Mortem corto: qué funcionó, qué falló, qué ajuste mañana.
5. Subir evidencia a Notion Bóveda de Evidencias si hubo entregable / nota clave.
6. Revisar Rutina de Apagado (Hangar Logístico) + programar automatic replies si aplica.
7. Dejar Orden de Batalla de mañana lista (3 prioridades ya elegidas).

### 2.3. Qué NO se duplica (5 reglas anti-caos)

1. **No duplicar fechas:**
   - La fecha oficial vive en Notion (Pipeline, Orden de Batalla, Calendar).
   - Obsidian `07_TABLERO` solo espeja, no crea fechas nuevas.
   - Todoist hereda la fecha de Notion para el hoy, no inventa vencimientos.

2. **No duplicar proyectos:**
   - El proyecto oficial vive en Notion (`10 PROYECTOS` espejo) + Obsidian `10 PROYECTOS`.
   - Todoist solo tiene tareas sueltas del proyecto, nunca el proyecto entero.
   - Si un proyecto no tiene entregable y fecha, no es proyecto, es área o recurso.

3. **No duplicar conocimiento:**
   - El conocimiento profundo vive en Obsidian (Zettels, MOCs, papers).
   - Notion solo guarda resumen + link a la nota Obsidian, no copia el contenido.
   - Todoist nunca guarda teoría, solo la acción que la aplica.

4. **No duplicar diarios:**
   - El diario oficial es Obsidian `01_DIARIO_DE_GUERRA/01_Daily_Logs`.
   - Notion no lleva diario paralelo; solo métricas (energía, MCs, checklist).
   - Todoist no lleva diario; su historial es solo cierre de tareas.

5. **No duplicar archivo:**
   - El archivo muerto vive en Obsidian `40 ARCHIVOS X` + Notion Archivo de Evolución.
   - Lo archivado no se edita; si revive, se crea nueva versión `_V[XX+1]`.
   - Borrar solo con confirmación explícita de Admin, nunca automático.

#### 3.4.1 CENTRAL ACADÉMICA — Gamificación

> Objetivo: gamificación académica total estilo RPG + Student Life OS.
> Base: `🏛️ CENTRAL ACADÉMICA`
> Props nuevas: **6**

| # | Propiedad | Tipo Notion | Fórmula / Config | Para qué sirve |
|---|-----------|-------------|------------------|----------------|
| 1 | Total | Number | Número entero, formato `Number` | Total de tareas / temas de la materia |
| 2 | Completadas | Number | Número entero, formato `Number` | Cuántas van hechas |
| 3 | Progress | Formula | `if(prop("Total") > 0, prop("Completadas") / prop("Total"), 0)` formato `Percent` | % real de avance, evita división por cero |
| 4 | Barra | Formula | `slice("██████████", 0, round(prop("Progress") * 10)) + slice("░░░░░░░░░░", 0, 10 - round(prop("Progress") * 10)) + " " + format(round(prop("Progress") * 100)) + "%"` | Barra visual + % en texto |
| 5 | XP | Formula | `round(prop("Progress") * 1000)` formato `Number` | Experiencia 0-1000 por materia |
| 6 | Nivel | Formula | `ifs(prop("Progress") >= 0.7, "Nivel III 🥇", prop("Progress") >= 0.3, "Nivel II 🥈", "Nivel I 🥉")` | Rango RPG automático |

Notas de fórmula:

- `Progress` usa `if Total>0` para no romper cuando la materia está recién creada con `Total = 0`.
- `Barra` usa `slice █░` de 10 caracteres para que se vea igual en móvil y PC.
- `XP` escala lineal: `Progress * 1000`.
- `Nivel` usa umbrales: `<30% = I`, `30-69% = II`, `>=70% = III`.

Demo 1 — Geografía:

- Materia: `Geografía — Examen Regiones Francia/Italia`
- `Total = 10`
- `Completadas = 3`
- `Progress = 3/10 = 0.3 → 30%`
- `Barra = ███░░░░░░░ 30%`
- `XP = round(0.3*1000) = 300`
- `Nivel = Nivel II 🥈` porque `0.3 >= 0.3`
- Interpretación: desbloqueó Nivel II con 300 XP.

Demo 2 — Programación:

- Materia: `Programación — POO + Estructuras`
- `Total = 8`
- `Completadas = 6`
- `Progress = 6/8 = 0.75 → 75%`
- `Barra = ████████░░ 75%` con `round(7.5)=8` según redondeo Notion
- `XP = round(0.75*1000) = 750`
- `Nivel = Nivel III 🥇` porque `0.75 >= 0.7`
- Interpretación: a 2 tareas del 100%, ya es rango oro.

Objetivo gamificación cumplido:

- Cada materia da XP.
- Cada avance mueve Barra.
- Cada 30% y 70% sube Nivel.
- Se replica sistema RPG sin pagar RPG Dashboard.

#### 4.4.4 Sintaxis Tasks dentro de las plantillas (formato `tasksPluginEmoji`)
Las plantillas E-100 ya dejan tareas con emojis que Tasks 8.4.0 entiende. Sintaxis oficial:
- `📅` = due date (vencimiento). Ejemplo: `- [ ] Repasar Anki alemán 📅 2026-09-23`
- `🔁` = recurrence (recurrencia). Ejemplo: `- [ ] Rutina apagado 🔁 every day 📅 2026-09-22`
- `⏫` = prioridad alta / highest. Ejemplo: `- [ ] Entregar monografía ⏫ 📅 2026-09-25`
- `🔼` = prioridad media / high-medium. Ejemplo: `- [ ] Leer paper 🔼 📅 2026-09-24`
- `🔽` = prioridad baja / low. Ejemplo: `- [ ] Ordenar inbox 🔽 📅 2026-09-26`
- `➕` = created date (creación, auto con `setCreatedDate: true`). Ejemplo: `- [ ] Idea E-100 ➕ 2026-09-22`
- `🏁` = start date (no empezar antes de). Ejemplo: `- [ ] Proyecto Alemania 🏁 2026-10-01 📅 2026-10-15`
- Extras que usa E-100: `✅ done date` (auto con `setDoneDate: true`), `⏳ scheduled`, `🛫 start` alias.

## 5. TODOIST — ARMA DE CORTO ALCANCE

### 5.1 Rol dentro de la Trinidad E-100

- Notion = gestionar. Obsidian = pensar. Todoist = ejecutar hoy.
- Todoist es el arma de corto alcance: tareas pequeñas, visibles en móvil, sin fricción.
- Principio: si tarda más de 2 minutos en registrarse, el sistema falla.
- Nada suelto: cada micro-tarea de Notion con fecha vive también en Todoist.
- Admin ejecuta desde Todoist, piensa en Obsidian, audita en Notion.

### 5.2 Credencial operativa

- Token API Todoist: `[REDACTED-ROTAR]`
- Uso: sincronización Notion → Todoist vía script / automatización local.
- Custodia: variable de entorno local, no se commitea, no se comparte.
- Alcance del token: lectura y escritura de proyectos, tareas, etiquetas y filtros personales.
- Rotación: si hay exposición, revocar desde Todoist > Ajustes > Integraciones y regenerar.

### 5.3 Los 5 proyectos base

Estructura mínima funcional. Ni uno más, ni uno menos para operar sin ruido.

### 5.4 Las 6 etiquetas operativas

### 5.5 Sync Notion ORDEN DE BATALLA + INVASIÓN SEMANAL → Todoist

- Origen Notion: BD `ORDEN DE BATALLA` (diaria) + `INVASIÓN SEMANAL` (semanal).
- Destino Todoist: Proyecto correspondiente + etiqueta `@hoy` o `@semana`.
- Dirección: unidireccional Notion → Todoist para ejecución. El cierre se audita en Notion.
- Frecuencia: diaria 06:30 (batalla del día) y lunes 07:00 (invasión semanal).
- Mapeo de campos:
  - `Nombre Notion` → `Título Todoist`
  - `Fecha` → `Due date Todoist`
  - `Proyecto / Materia` → `Proyecto Todoist (Trabajo/Estudio/Alemania C1/Personal)`
  - `Prioridad Notion` → `P1-P4 Todoist`
  - `URL Notion` → `Descripción Todoist con link de retorno`
- IDempotencia: se guarda `notion_id` en descripción para no duplicar en re-sync.
- Cierre del loop: al completar en Todoist, revisión nocturna marca avance en Notion y Obsidian Daily Log.

### 5.6 Nota crítica — filtros API 404/410 gestión manual

- Estado API Todoist filtros: endpoints de filtros avanzados devuelven `404` / `410` en cuentas / versiones actuales.
- Causa: deprecación de filtros legacy y migración a vistas guardadas en cliente.
- Impacto: no se puede crear / listar filtros complejos por API de forma fiable.
- Mitigación E-100: gestión manual de filtros en app Todoist (móvil + desktop).
- Filtros manuales recomendados a crear en UI:
  - `Hoy sin fricción`: `@hoy & !@esperando`
  - `Urgente puro`: `@urgente & @hoy`
  - `En espera`: `@esperando | @delegado`
  - `Casa`: `@casa & @semana`
  - `Alemania hoy`: `#Alemania C1 & @hoy`
- Procedimiento: Admin crea filtros una vez en UI, el script solo usa proyectos + etiquetas, nunca filtros API.
- Verificación: si el sync falla con 404/410, loguear y continuar — no aborta la sincronización de tareas.

### 5.7 Objetivo operativo

- Objetivo único: ejecutar hoy sin fricción.
- Métrica: 0 tareas `@hoy` abiertas a las 23:59 o con post-mortem escrito.

- Tiempo de planificación: <10 minutos para convertir Inbox en plan `@hoy`.

## 7. GPU FIX UNIVERSAL

### 7.1 Problema raíz

- Hardware: iGPU Intel UHD, RAM total 12GB, sin dGPU dedicada.
- Síntoma: crash 100% en apps Electron / Chromium con aceleración ANGLE por defecto.
- Manifestación: pantalla negra, freeze, `GPU process exited`, reinicio de Notion / Discord / VS Code.
- Impacto E-100: Notion (Centro de Operaciones) inusable, OmniRoute dashboard caído, Discord sin voz.
- Diagnóstico: ANGLE intenta `D3D11` / `GL` en driver Intel inestable + memoria compartida limitada.
- Conclusión: deshabilitar GPU HW y forzar CPU rendering para estabilidad total.

### 7.2 Solución estándar — SwiftShader CPU rendering

- Flag maestro: `--use-angle=swiftshader`
- Efecto: ANGLE usa SwiftShader (CPU Vulkan / GL emulado), cero dependencia de driver Intel.
- Complementos: `--disable-gpu-sandbox --no-sandbox --disable-hardware-acceleration` según app.
- Costo: +5-12% CPU, pero 0 crashes. Prioridad E-100 = estabilidad sobre fps.
- Verificación: `chrome://gpu` debe mostrar `SwiftShader` y `Software only`.
